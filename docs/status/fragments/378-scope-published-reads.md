Scoped `GET /api/sessions`, `GET /api/threads`, `GET /api/sessions/:id`, and `GET /api/sessions/:id/transcript` by `published`: an unauthenticated caller now only sees published sessions (404 not 403 on the by-id routes, published-before-`?q=` on the list route), gated by a new `req.authed` set once in `auth.js` rather than re-derived per route. Prerequisite groundwork for [#379](https://github.com/msdixon/secret-cabinet/issues/379)'s public read tier — a behavioral no-op today since the passphrase gate still blocks unauthenticated `/api/` traffic before these handlers run.
