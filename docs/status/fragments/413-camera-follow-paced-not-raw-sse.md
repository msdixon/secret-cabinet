Fixed the camera swinging to later speakers while an earlier one was still visibly mid-turn ([#413](https://github.com/msdixon/secret-cabinet/issues/413)): `setSpeaking()` was called the instant each SSE `speaking` event arrived, which is raw generation pace and routinely outruns the paced, one-turn-at-a-time reveal `witness.js`'s `#400` live-turn queue built for exactly this reason — most visible on long, multi-beat turns, where generation for two or three speakers ahead can finish before the first one's beats are done being shown. Moved the camera call into `advanceLiveTurnQueue` itself, so framing now rides the same front-of-queue signal as the room cards and voice do, plus a matching reset when the queue drains or the stage resets. Verified live against a real multi-member, multi-beat convene.
