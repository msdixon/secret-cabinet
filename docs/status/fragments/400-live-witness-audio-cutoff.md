[#400](https://github.com/msdixon/secret-cabinet/issues/400) fixed the live-convene half of #336 that PR #341 never actually touched: `liveSpeech()`/`flushRoomHold()` in `public/js/witness.js` called `Voice.speak()` as fast as text streamed in, with nothing gating a beat's speech on the previous one finishing, so a member's audio got cut off mid-sentence on nearly every beat. A serialized live-speech queue now defers each beat's `Voice.speak()` call until the prior one's promise resolves (reset on stage exit/collapse so a queued beat can't talk into an already-left session). Separately, `speakViaElevenLabs` (`public/js/voice.js`) never applied `speedMultiplier` to the `<audio>` element's `playbackRate`, so the witness-speed control only ever changed text pacing, never the ElevenLabs audio most sessions actually hear — now set and clamped the same way the Web Speech path's rate is. Both fixes verified against real ElevenLabs synthesis in a live convene (not mocked), per #341's own admitted gap. 4 new tests, 949 total.
