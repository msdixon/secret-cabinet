[#400](https://github.com/msdixon/secret-cabinet/issues/400) fixed the live-convene half of #336 that PR #341 never actually touched. A first pass just serialized `Voice.speak()` calls in `public/js/witness.js`, which stopped audio cutting itself off but — caught in real live testing — left the *visual* side (typing indicators, settled cards) advancing unpaced, so the room raced far ahead of what was actually playing (a member's next turn, or a different member's, already on screen before the previous line's audio had even started). Replaced #279's per-member, WPM-only room hold with a single global live turn queue: `liveTypingStart`/`liveTypingSet`/`liveSpeech` now push onto one FIFO where only the front turn is ever rendered, paced by real `Voice.speak()` duration (WPM fallback when voice is off), extended to stage mode (previously entirely unpaced) and made lossless (#279 used to silently drop a turn superseded mid-hold). Separately, `speakViaElevenLabs` (`public/js/voice.js`) never applied `speedMultiplier` to the `<audio>` element's `playbackRate`, so the witness-speed control only ever changed text pacing, never the ElevenLabs audio most sessions actually hear — now set and clamped the same way the Web Speech path's rate is. Verified against real ElevenLabs synthesis in a live multi-member convene (not mocked), per #341's own admitted gap — confirmed via instrumented timing that card settling now tracks audio start/end instead of racing ahead, and that a mid-session speed change reaches the next beat. 949 total tests.
