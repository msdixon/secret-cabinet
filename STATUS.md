# STATUS.md

Dated, one-line-per-entry log of what shipped or changed. Newest first. Append a new entry whenever something ships, a decision gets made, or a notable bug gets found/fixed — don't rewrite history above it.

**Entries are 1-3 sentences plus the PR/issue link — not a restatement of the PR body.** The PR carries the reasoning, the alternatives considered, and the verification steps; that's what it's for, and it stays attached to the diff permanently. This file is read into context at the start of most sessions, so its size has an ongoing cost beyond scrolling — see [#275](https://github.com/msdixon/secret-cabinet/issues/275), filed after entries drifted to ~4x their prior length in a matter of weeks.

**When this file crosses ~60KB, roll the oldest entries into `docs/status/ARCHIVE-<range>.md`** and leave a pointer here, same as the archive below. Size-triggered, not calendar-triggered — a fixed schedule doesn't track what actually made the file big.

For the *why* behind any entry, check the linked PR/issue first; deeper narrative context (what was tried, what was rejected, collaboration notes) lives in Claude's memory, not here. For current direction and open decisions, see [PROJECT.md](PROJECT.md).

Deliberately scoped to just these two breakpoints, not the member-specific parts of a speaker's own system prompt (character file, voice exemplar, residue) — those don't repeat *across* speakers, so caching them would only pay off on a same-speaker repeat within a round, a narrower win than the issue judged worth the added complexity of a second system-tier split. 461 tests, up from 441, including request-shape coverage proving `callDirector`/`callSpeakerTurn` actually send the `cache_control` blocks in the right place, not just that the pure split functions return the right shape.
